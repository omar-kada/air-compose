# REST API Reference

AirCompose exposes a REST API and WebSocket endpoint under `/api/`. All endpoints require authentication via a Bearer token (obtained through login or OIDC).

## Base URL

```
http://localhost:5005/api/
```

## Authentication

### Register (First User Only)

The first user is registered directly. Subsequent registrations require manual DB reset.

```bash
curl -X POST http://localhost:5005/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "your-password"}'
```

### Check Registration Status

```bash
curl http://localhost:5005/api/auth/register
```

Returns `{ "registered": true, "oidc": false }` if a user is already registered.

### Login

```bash
curl -X POST http://localhost:5005/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "your-password"}' \
  -c cookies.txt
```

On success, a `Set-Cookie` header is returned with the authentication token.

### Refresh Token

```bash
curl -X POST http://localhost:5005/api/auth/refresh \
  -b cookies.txt \
  -c cookies.txt
```

### Logout

```bash
curl -X POST http://localhost:5005/api/auth/logout \
  -b cookies.txt
```

### OIDC Login

```bash
# Initiate OIDC login
curl -L http://localhost:5005/api/oidc/login

# Handle callback with code and state
curl http://localhost:5005/api/oidc/callback?code={code}&state={state}
```

## API Endpoints

### Config

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/config` | Retrieve the current configuration |
| `POST` | `/api/config` | Update the configuration |

**Get Config:**
```bash
curl http://localhost:5005/api/config -b cookies.txt
```

**Set Config:**
```bash
curl -X POST http://localhost:5005/api/config \
  -b cookies.txt -H "Content-Type: application/json" \
  -d '{"globalVariables": {"TZ": "UTC"}, "services": {"web": {"PORT": "8080"}}}'
```

### Deployments

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/deployment?limit=20&offset=0` | List deployments (paginated) |
| `POST` | `/api/deployment` | Sync and deploy if changes exist |
| `GET` | `/api/deployment/{id}` | Get deployment details |

**List Deployments:**
```bash
curl "http://localhost:5005/api/deployment?limit=20&offset=0" -b cookies.txt
```

Response includes pagination info:
```json
{
  "items": [
    {
      "id": "1",
      "title": "Manual Deploy",
      "author": "",
      "time": "2024-01-15T10:30:00Z",
      "endTime": "2024-01-15T10:32:00Z",
      "diff": "...",
      "status": "success"
    }
  ],
  "pageInfo": { "hasNextPage": false, "endCursor": "0" }
}
```

**Trigger Sync:**
```bash
curl -X POST http://localhost:5005/api/deployment -b cookies.txt
```

**Get Deployment Details:**
```bash
curl http://localhost:5005/api/deployment/1 -b cookies.txt
```

Response includes deployment details with associated files and events:
```json
{
  "id": "1",
  "title": "Manual Deploy",
  "author": "",
  "time": "2024-01-15T10:30:00Z",
  "endTime": "2024-01-15T10:32:00Z",
  "diff": "...",
  "status": "success",
  "files": [
    {
      "oldFile": "services/web/compose.yaml",
      "newFile": "services/web/compose.yaml",
      "diff": "@@ -1,5 +1,6 @@"
    }
  ],
  "events": [
    {
      "ID": 1,
      "time": "2024-01-15T10:30:00Z",
      "msg": "Deployment started",
      "type": "DEPLOYMENT_STARTED",
      "objectId": 1,
      "objectName": "Manual Deploy"
    }
  ],
  "commit": "abc123",
  "repo": "https://github.com/...",
  "branch": "main"
}
```

## WebSocket API

AirCompose exposes a WebSocket endpoint for real-time updates:

```
ws://localhost:5005/api/ws
```

### Client → Server Messages

| Type | Fields | Description |
|---|---|---|
| `startLogs` | `{ previousLines: number }` | Request log history (last N lines) |
| `endLogs` | `{}` | Stop receiving log messages |

### Server → Client Messages

| Type | Fields | Description |
|---|---|---|
| `log` | `{ msg, time, level, meta }` | A log line |
| `previousLogs` | `LogLine[]` | Log history when starting log stream |
| `newDeployment` | `Deployment` | A new deployment has started |
| `event` | `{ type, msg, deploymentId, isNotification }` | An event occurred |
| `error` | `{ code, message }` | An error occurred |

## Error Responses

All API errors follow this format:

```json
{
  "code": "SERVER_ERROR",
  "message": "Description of the error"
}
```

| Code | Description |
|---|---|
| `INVALID_TOKEN` | Authentication token is invalid or expired |
| `INVALID_CREDENTIALS` | Username or password is incorrect |
| `INVALID_REQUEST` | Request parameters are invalid |
| `NOT_ALLOWED` | Action is not permitted |
| `DISABLED` | Feature is not enabled |
| `NOT_FOUND` | Resource was not found |
| `SERVER_ERROR` | Internal server error |
