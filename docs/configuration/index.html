Configuration

AirCompose stores its configuration in a config.yaml file located in the working directory (AIR_COMPOSE_WORKING_DIR). The configuration can be edited through the UI or by modifying the file directly.

Configuration File​

The config.yaml file has the following structure:

settings:
  git:
    repo: "https://github.com/your-org/air-compose-config"
    branch: "main"          # optional, defaults to "main"
    username: "your-username"
    token: "your-token"
  schedule:
    cron: "@hourly"         # cron expression for auto-sync
    retriesOnUnhealthy: 3   # number of redeploy attempts on unhealthy
    retryDelay: 30000       # milliseconds between retries
  notifications:
    notificationURL: "shoutrrr://..."  # Shoutrrr-compatible URL
    notificationTypes:
      - "DEPLOYMENT_STARTED"
      - "DEPLOYMENT_SUCCESS"
      - "DEPLOYMENT_ERROR"
      - "HEALTH_CHANGE"
      - "NEW_COMMIT"
      - "CONFIGURATION_UPDATED"
      - "PASSWORD_UPDATED"
      - "SESSION_REUSED"
  oidc:
    issuerURL: "https://your-oidc-provider"
    clientID: "your-client-id"
    clientSecret: "your-client-secret"
environment:
  GLOBAL_VAR: "value"
services:
  service1:
    PORT: "8080"
    API_KEY: "secret"
  service2:
    PORT: "3000"

Settings​

Git Settings​

FieldDescriptionRequired
git.repoURL of the Git repository containing compose stacksYes
git.branchBranch to track (defaults to main)No
git.usernameGit username for HTTP authenticationOnly for private repos
git.tokenPersonal access token for Git authenticationOnly for private repos

Schedule Settings​

FieldDescriptionDefault
schedule.cronCron expression for automatic syncEmpty (disabled)
schedule.retriesOnUnhealthyMax redeploy attempts when containers are unhealthy0
schedule.retryDelayDelay between retries (milliseconds)30000

Notifications​

AirCompose uses Shoutrrr for notifications, supporting email, Slack, Discord, Telegram, and many other services.

FieldDescription
notificationURLShoutrrr-compatible URL for notifications
notificationTypesList of event types to trigger notifications

OIDC (OpenID Connect)​

FieldDescription
issuerURLOIDC provider's issuer URL
clientIDClient ID registered with the provider
clientSecretClient secret registered with the provider

Environment Variables​

Global environment variables applied to all services:

environment:
  TZ: "UTC"
  LOG_LEVEL: "info"

Per-Service Overrides​

Environment variables specific to individual services:

services:
  my-app:
    PORT: "8080"
    DATABASE_URL: "postgres://..."
note

Per-service variables override global variables.

CLI Parameters​

In addition to the config.yaml, AirCompose accepts CLI flags and environment variables. Priority is: CLI flag > environment variable > default value.

Run Command​

FlagEnv VariableDefaultDescription
-cAIR_COMPOSE_CONFIG_FILE./config.yamlPath to the config file
-dAIR_COMPOSE_WORKING_DIR./dataData directory
-sAIR_COMPOSE_SERVICES_DIR.Services directory
-iAIR_COMPOSE_DOCKER_IMAGEghcr.io/omar-kada/air-composeDocker image for self-update
-wAIR_COMPOSE_ADD_WRITE_PERMfalseAdd write permissions to created files
-pAIR_COMPOSE_PORT5005API/UI port
-lAIR_COMPOSE_LOG_LEVELINFOLog level (DEBUG, INFO, WARN, ERROR)
-fAIR_COMPOSE_LOG_FILE./air-compose.logLog file path

Redeploy Command​

FlagEnv VariableDefaultDescription
-dAIR_COMPOSE_WORKING_DIR./dataData directory
-sAIR_COMPOSE_SERVICES_DIR.Services directory
-lAIR_COMPOSE_LOG_LEVELINFOLog level
-fAIR_COMPOSE_LOG_FILE./air-compose.logLog file path

Feature Flags​

Feature flags control which UI features are available and are read from the container's environment at startup. These are not the logging variables — only the four below toggle UI capabilities. See the Environment Variables reference for logging options like AIR_COMPOSE_HUMAN_LOG.

Env VariableDefaultDescription
AIR_COMPOSE_DISPLAY_CONFIGtrueEnable config page in UI
AIR_COMPOSE_EDIT_CONFIGtrueAllow editing compose configuration from the UI
AIR_COMPOSE_EDIT_SETTINGStrueAllow editing settings (Git, OIDC, notifications) from the UI
AIR_COMPOSE_DISPLAY_CMD_LOGSfalseDisplay command execution logs

Data Directory Layout​

The working directory is organized as follows:

working-dir/
├── config.yaml        # Configuration file
├── air-compose.log    # Application log file
├── db/                # SQLite database directory (created by GORM)
│   └── air-compose.db # SQLite database
├── repo/              # Git repository clone
│   └── services/
│       ├── service1/
│       └── service2/
